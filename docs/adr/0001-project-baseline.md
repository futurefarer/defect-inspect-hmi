# ADR 0001：项目工程基线

- **状态**：已接受
- **日期**：2026-11-14
- **决策者**：futurefarer

## 背景

本项目是转行学习项目，目标是逐步演进为工业视觉缺陷检测上位机，并作为求职作品集。
当前代码是一个约 70 行的单文件程序（读图 → 灰度 → 二值化），需要先建立可复现的工程基线。

## 决策

1. **版本控制**：Git + GitHub（Public 仓库）作为唯一事实来源。
2. **构建系统**：CMake（C++17），Debug/Release 可切换。
3. **代码结构**：当前阶段保持单个可执行文件，不提前拆分库；当出现明确的复用/测试痛点后再拆分。
4. **技术栈引入顺序**：OpenCV 先行；Qt 在 M1（界面）阶段引入；SQLite/JSON 在 M2 阶段引入。
5. **持续集成**：GitHub Actions 在每次 push / PR 时自动构建。
6. **代码风格**：clang-format（Google 基础，4 空格缩进）。
7. **协作流程**：Issue → feature 分支 → Pull Request → CI → Review → 合并。

## 理由

- 学习阶段最重要的是“每一步都能理解和复现”，而不是一开始就做完整架构。
- 先用单文件跑通图像链路，再在真实痛点（界面、切换算法、卡顿）出现时引入设计。
- CI 尽早建立，保证每次提交都能构建，避免“本地能跑、换机器就崩”。

## 后果

- 正面：构建简单、上手快、可复现；CI 提供基础质量保障。
- 负面：后续引入 Qt 和多模块时需要重构（已在计划中，属于预期成本）。
- 后续 ADR 将记录：界面层引入、线程模型、算法抽象、配置与数据存储等决策。
